# 3분 시연 — 장소 탐색에서 사진 카드뉴스까지

## 준비

Node 24 이상에서 `npm ci`, `npx playwright install chromium`, `npm run dev`를 실행하고 [로컬 앱](http://127.0.0.1:3000)을 연다. API 키 없이 **데모** 모드를 사용한다. 지도는 온라인 타일을 사용하므로 연결을 확인한다. 장소 사진은 로컬 자산이다.

율동공원을 선택해 정상 데모 한 건을 미리 만들어 둔다. 시연 중 생성이 길어지면 제작 기록에서 이 결과를 열되, 새 요청의 결과인 것처럼 설명하지 않는다. 사진 출처는 [장소·사진 출처](place-sources.md), 화면 구성 근거는 [디자인 참조](design-references.md), 현재 범위는 [설계](superpowers/specs/2026-09-13-tourism-platform-design.md)·[구현 계획](superpowers/plans/2026-09-13-tourism-platform.md)을 따른다.

## 0:00–0:40 — 도시 탐색과 실제 장소

“성남의 관광지를 찾고, 공식 자료와 실제 사진으로 홍보물을 만드는 작업 공간입니다. 대시보드의 작업 수와 상태는 저장된 제작 기록에서 가져옵니다.”

사이드바의 **관광지 탐색**을 연다. 전국 지도에서 **성남 확대**를 누르고 율동공원을 검색해 목록 또는 지도에서 선택한다. 실제 사진·주소·공식 안내·사진 출처를 보여준다.

“현재 등록한 장소는 8곳입니다. 전국 지도 위에서 탐색하지만 전국 관광지 데이터베이스는 아닙니다. 운영정보가 확인되지 않은 항목은 임의로 무료나 상시 개방이라고 채우지 않습니다.”

## 0:40–1:20 — 선택한 장소로 제작

**이 장소로 카드뉴스 만들기 → 데모 → 카드뉴스 제작하기**를 누른다. 준비한 결과를 여는 경우 제작 기록에서 해당 작업을 선택한다.

“지금은 장소별 공식 발췌와 준비된 문구를 사용하는 데모입니다. 자유 입력을 이해해 작성한 실제 AI 결과가 아니며, 텍스트·이미지 모델 API는 호출하지 않았습니다.”

카드 4장에 율동공원 사진과 근거가 연결되는지, 마지막 카드의 **상상 장면** 표시를 확인한다. 첫 카드의 문장 근거·공식 원문·검수 기록을 연다.

“근거 지지, 근거와 충돌, 근거 부족을 구분합니다. 마지막 문구가 상상이어도 현재 사용한 장소 사진은 실제 사진임을 표시합니다.”

## 1:20–2:05 — 사진 편집과 버전

한 카드의 사진 편집을 열고 초점·확대를 조절한다. 미리보기를 확인한 뒤 **사진 구도 저장**을 누른다. 대상 카드의 사진만 바뀌고 문구와 다른 카드는 유지되는지 보여준다.

“사진 변경도 콘텐츠 변경입니다. 새 버전으로 저장되면서 이전 검수·승인·출력 연결이 무효화됩니다. 다시 검수해야 최신 파일을 전달할 수 있습니다.”

**사진 바꾸기**의 기본 사진 복원·권한 확인 업로드와 **AI 이미지로 새롭게 표현하기**를 짧게 보여준다.

“AI 이미지는 별도 연결 설정이 필요합니다. 지금은 실제 생성 버튼의 성공이나 품질을 시연하지 않습니다. 연결하면 선택한 카드와 참조 사진을 바탕으로 생성하며, 결과는 AI 생성으로 표시합니다. 참조 사진의 저작자와 라이선스 조건도 이어집니다.”

## 2:05–2:40 — 재검수·승인·파일

재검수를 실행하고 콘텐츠·검수 버전이 같은지 확인한다. 담당자 이름을 입력하고 **최종 결과 승인** 후 패키지를 내려받는다. 실제 PNG의 사진·크롭·한글과 ZIP의 대본·출처·검수 파일을 보여준다.

“자동 검수 통과와 담당자 승인은 다른 단계입니다. 문구나 사진을 다시 바꾸면 재검수가 필요합니다. 다운로드한 출처 파일에는 사용한 이미지의 귀속정보도 포함됩니다.”

## 2:40–3:00 — 기록과 검증 범위

사이드바의 **제작 기록**을 열어 현재 작업을 다시 선택한다.

“장소 탐색부터 저장된 작업의 편집까지 이어집니다. 현재 확인하는 것은 로컬 실행과 실제 사진 출력입니다. 실제 텍스트 모델의 판단·수정 품질과 AI 이미지 품질은 API 설정 후 별도로 검증해야 합니다. 지금 데모로 정확도나 작업 시간 절감을 주장하지 않습니다.”

## 선택 시연: 기존 박물관 오류 복구

시간이 별도로 있을 때 판교박물관의 **시연·비교 설정 → 에이전트 → 근거 없는 역사적 연결**을 실행한다. 준비된 인과관계 오류가 검수되고, 신규 근거가 없는 재검색 뒤 확인된 발굴 설명으로 수정되는 과정을 보여준다. 이는 과거부터 유지한 결정적 회귀 사례이며 현재 관광지 전체의 실제 AI 성능 평가가 아니다.

공식 사이트 연결은 `npm run sources:probe -- 판교박물관 관람료`로 별도 확인할 수 있다. 결과는 실행 시점의 웹 내용에 따라 달라진다. 고정 fixture의 인용 수와 실제 웹 수집 결과를 혼합하지 않고 화면에 나온 기록만 설명한다.

## 시연 전 확인

- 데모 모드와 실제 모델 API 시도 수를 확인한다. 키가 없는 상태에서 AI 이미지 생성 성공을 주장하지 않는다.
- 실제 사진, AI 생성 이미지, 상상 문구의 표시를 구분한다. CC BY-SA 사진의 파생물에는 [해당 사진의 이용 조건](place-sources.md#사진-귀속정보)이 이어진다.
- 사진 변경 후 버전 증가·승인 해제·재검수와 최종 PNG의 크롭을 확인한다.
- ZIP의 검수 JSON은 출력 시점 스냅샷이다. 이후 담당자 승인의 최신 기록은 앱의 Run에 있다.
- 실제 모델 smoke는 설정과 평가 예산을 갖춘 후 별도로 실행한다. 최종 검증 수치는 [평가 문서](evaluation.md)의 실제 기록을 따른다.
- 승인은 로컬 담당자 확인 기록이다. 외부 공개 배포나 SNS 게시는 수행하지 않는다.
