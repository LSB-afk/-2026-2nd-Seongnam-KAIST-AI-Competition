# 3분 시연 대본

## 준비

`npm ci`, `npx playwright install chromium`, `npm run dev` 후 http://127.0.0.1:3000 을 연다. API 키 없이 실행하는 ‘데모’ 모드를 사용한다. ‘시연·비교 설정’은 에이전트 / 근거 없는 역사적 연결을 선택한다. 이 시연은 준비된 응답의 오류 복구 경로이며 실제 AI 판단을 보여주는 것은 아니다.

공식 웹 수집 결과를 함께 설명하려면 시연 전에 다음 명령을 별도로 실행한다. 라이브 웹 응답을 기다리느라 3분 진행이 끊기지 않도록 결과 JSON을 미리 열어둔다.

```bash
npm run sources:probe -- 판교박물관 관람료
```

## 0:00–0:25 — 요청과 실행 모드

“청소년에게 판교박물관을 소개하는 카드뉴스 4장을 요청합니다. 마지막 장은 미래 문화공간의 상상입니다. 오늘 화면은 저장된 응답 데모로, 실제 모델 API 시도는 0회입니다.”

‘카드뉴스 제작하기’를 누르고 실행 모드와 API 시도 횟수를 보여준다.

## 0:25–1:15 — 근거 부족 발견과 복구

“초안에 ‘이 문화유산의 기술이 오늘날 판교 AI 산업으로 이어졌다’는 오류를 의도적으로 넣었습니다. 해당 설명을 검수하고 추가 근거를 확인한 뒤 필요한 문구만 수정합니다.”

‘제작 기록’과 ‘검색과 근거 수집’을 연다. 최초 근거 3개, 재검색의 신규 근거 0개를 보여준다.

“이번 데모 재검색에서는 인과관계를 지지할 새 근거가 나오지 않았습니다. 이를 발견한 것처럼 꾸미지 않고, 이미 확인한 발굴조사 설명으로 고친 뒤 다시 검사합니다.”

세 번째 카드를 선택하고 ‘수정 내역’에서 잘못된 연결과 수정된 발굴조사 기간을 비교한다. 이 과정으로 실제 AI 정확도 향상을 주장하지 않는다.

## 1:15–1:55 — 주장·원문·검수 이력

첫 카드의 ‘문장 근거’를 열어 개관일 설명과 인용문, 공식 출처, 검수 당시 원문 스냅샷을 연결해 보여준다. 과거 검수 기록과 현재 판정을 구분하고 마지막 카드의 ‘상상 장면’을 확인한다.

“판정은 근거 지지, 근거와 충돌, 근거 부족을 구분합니다. 자료가 없다는 이유로 거짓이라고 단정하지 않습니다. 실제 모델 모드에서는 제목·본문·대본을 원자 주장으로 검수하지만, 지금은 준비된 문구를 확인하는 데모입니다.”

## 1:55–2:30 — 승인·전달·담당자 편집

담당자 이름을 입력하고 콘텐츠·검수 버전이 같은지 확인한 뒤 ‘최종 결과 승인’을 누른다. ZIP의 카드 4장·대본·출처·검수 파일을 보여준다.

“자동 검수 통과와 사람 승인을 구분합니다. 직접 편집하면 새 버전이 되어 이전 승인이 무효화됩니다. 담당자가 편집한 카드는 자동으로 덮어쓰지 않고 변경 제안을 남깁니다.”

시간이 남으면 편집창을 열어 설명한다. 제안이 있는 별도 실행에서는 ‘제안을 편집창에 불러오기’를 보여주되, 이 버튼만으로 저장·검수·승인이 완료됐다고 말하지 않는다. 저장 후 다시 검수해야 한다.

## 2:30–3:00 — 실제 자료 탐색과 남은 검증

미리 준비한 `source-probe.json`을 잠깐 보여준다.

“공식 웹 수집은 별도로 두 번 실행했습니다. 개관일 검색에서 인용 2개를 얻은 뒤, 관람료 재검색에서 8페이지를 방문해 새 후보 2개를 추가했습니다. 총 4개가 보존됐습니다. 무료 관람과 무료 주차 안내는 다른 사실이며, 이 명령도 모델 호출은 0회입니다.”

“실제 AI 생성과 오류 수정은 API 키·모델·가격·비용 설정이 없어 아직 검증하지 못했습니다. 설정 후 같은 자료와 예산으로 비교하는 명령은 마련했습니다. 지금 결과만으로 정확도 향상이나 사람의 시간 절감을 주장하지 않습니다.”

## 시연 전 확인

- 화면에 ‘데모’, 실제 모델 API 0회가 표시되는지 확인한다.
- fixture 재검색의 신규 근거 0개와 별도 웹 probe의 최초 2개·추가 2개·누적 4개를 혼합하지 않는다.
- probe 결과는 실행 시점의 웹 내용에 따라 달라진다. 화면의 실제 기록을 기준으로 설명한다.
- 실제 모델 smoke는 설정 후 `npm run eval:smoke`로 실행한다. 평가 전체 상한 `EVAL_MAX_COST_USD`도 필요하다.
- ZIP의 검수 기록은 출력 시점 스냅샷이며, 이후 사람 승인의 최신 기록은 앱에 있다.
- 데모는 자동 게시하지 않는다. 승인 기록은 로컬 담당자 확인 기록이며 인증된 서명이 아니다.
