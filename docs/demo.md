# 3분 시연 — 근거를 확인하고 문제 문구를 고치는 제작 과정

기준일: 2026-09-14. 3분은 연습용 구성이다. 공식 발표 시간과 평가표는 미확인이므로 공지 후 조정한다. 시연의 중심은 문화홍보 담당자의 작업, AI의 판단 지점, 수정 전후와 남은 확인 사항이다.

## 준비와 실행 구분

앱 실행은 [README의 로컬 실행](../README.md)을 따른다. 판교박물관을 선택하고 **청소년 이야기 → 데모 → 시연·비교 설정 → 에이전트 → 근거 없는 역사적 연결**로 한 건을 준비한다. 시연 전에 최종 상태, 준비된 오류의 수정 전후, 검색·검수 기록, PNG·ZIP을 직접 확인한다. 결과가 보류이면 보류 이유를 보여줄 준비를 한다. 새 제작이 시간 안에 끝나지 않으면 해당 저장 기록을 연다.

| 보여주는 자료 | 반드시 밝힐 내용 | 해석 가능한 범위 |
| --- | --- | --- |
| fixture 데모 | 준비된 공식 발췌·문구·판단 규칙이며 실제 텍스트 모델 호출 없음 | 문제 발견·수정·버전·파일 전달의 구현 흐름 |
| live 실시간 실행 | 실제 모델·입력·자료·프롬프트 버전, 시각, API 시도와 최종 상태 | 해당 조건의 실제 실행 사례. 일반 성능은 별도 평가 필요 |
| 저장 결과 또는 녹화 | 원래 실행 모드, 생성 시각, 모델·조건, 지금은 기록을 여는 중이라는 사실 | 기록된 해당 실행. 실시간 실행으로 소개하지 않음 |

저장 결과·녹화는 발표 자료의 제시 방식이며 별도 앱 실행 모드가 아니다. 현재 환경에는 실제 텍스트·이미지 모델 설정이 없어 기본 시연은 fixture다. 실제 AI 기록이나 녹화는 확보 전이며 존재하는 것처럼 소개하지 않는다. 이후 live를 사용하려면 설정·예산·실행 기록을 확인한다. live 실패 시 fixture로 바꾸면 전환 사실부터 설명한다.

## 0:00–0:25 — 사용자와 확인할 문제

“성남 문화시설의 홍보 담당자가 공식 자료를 찾고, 독자에 맞게 다시 쓰고, 사실을 검토하는 과정을 돕습니다. 이런 반복이 제작 부담이라는 가설을 세웠고, 담당자 인터뷰와 업무 시간 비교는 앞으로 확인할 부분입니다. 콘텐츠를 접하는 시민은 별도의 수혜자입니다.”

홈에서 판교박물관 제작으로 진입한다. 수요를 입증한 인터뷰나 절감 수치가 없는 상태에서는 임의의 경험담·숫자를 넣지 않는다.

## 0:25–0:50 — 장소·자료·요청과 시연 조건

장소 상세의 공식 자료와 사진 출처, 청소년 대상의 제작 목적을 보여준다.

“지도는 장소와 자료를 고르는 진입점이고 타미는 사용 안내입니다. 핵심은 이 요청을 작성한 뒤, 근거 검수 결과에 따라 다시 조사하거나 문제 문구를 고치는 과정입니다. 지금은 준비된 응답을 쓰는 데모이며 실제 AI 판단 성능을 보여주는 것은 아닙니다.”

시연·비교 설정의 **근거 없는 역사적 연결**을 보여준 뒤 제작하거나 준비한 기록을 연다. 오류는 의도적으로 넣었다고 명시한다.

## 0:50–1:50 — 근거 판정 → 추가 확인 → 수정 또는 보류

문제 카드와 수정 이력을 열어 주입 문장 “이 문화유산의 기술이 오늘날 판교 AI 산업으로 이어졌다.”를 보여준다.

“공식 자료가 문화유산을 설명하더라도 오늘날 산업으로 기술이 계승됐다는 주장까지 입증하지는 않습니다. 근거가 없다는 것은 거짓 확정과 다릅니다. 실제 AI 실행에서는 제목·본문·대본의 사실을 나누고 지지, 충돌, 불충분을 판단합니다.”

검색·근거 기록에서 추가로 확인한 정보와 새 근거 수를, 수정 이력에서 실제 실행의 **수정 전 문장 → 수정 이유·근거 → 수정 후 문장 → 재검수 버전**을 순서대로 보여준다. 준비한 데모 규칙이 고친 내용을 모델의 자발적 판단으로 설명하지 않는다. fixture에 원자 판정 기록이 없다면 live 검수 화면인 것처럼 제시하지 않고 데모의 문제·근거·수정 기록을 사용한다.

“검수 결과에 따라 필요한 정보만 다시 찾고 문제가 있는 부분을 고칩니다. 해결하지 못하거나 상한에 도달하면 검토 필요로 멈춥니다. 담당자가 직접 편집한 문구는 자동으로 덮어쓰지 않고 제안으로 남깁니다.”

미해결 실행이면 성공으로 바꾸어 설명하지 말고 중단 이유·남은 확인 항목을 보여준다. live 기록을 확보한 경우에도 해결 사례만 골라 전체 성공률로 표현하지 않는다.

## 1:50–2:20 — 담당자 확인과 결과 전달

공식 원문, 현재 콘텐츠·검수 버전, 카드 4장과 마지막 장의 상상 표시를 확인한다. 승인 대기 상태라면 담당자 이름을 입력하고 **최종 결과 승인** 후 PNG·ZIP을 연다. 보류 상태라면 다운로드 성공을 시연하지 않고 준비된 정상 데모 기록으로 전환했음을 밝힌다.

“자동 검수와 담당자 확인은 다른 단계입니다. 문구나 사진을 바꾸면 다시 검수해야 합니다. 이 승인은 로컬 확인 기록이며 기관의 공식 게시나 자동 SNS 업로드는 아닙니다.”

## 2:20–3:00 — 증거와 한계, 다음 측정

실행 정보의 모드·API 시도·상한과 [평가 기록](evaluation.md)을 보여준다.

“현재는 장소별 제작, 검수·수정 이력, 편집 후 재검수와 실제 파일 전달을 확인했습니다. 실제 모델의 판단 품질과 담당자 업무 시간 절감은 아직 측정하지 않았습니다. 담당자의 기존 방식과 서비스 사용을 짝 비교해 승인 가능한 결과까지의 시간, 사람 수정, 남은 미지원 사실, 실패와 비용을 함께 기록하겠습니다.”

[현장 질문지](field-validation.md)와 [빈 비교 CSV](templates/field-workflow-pairs.csv)를 준비물로 보여준다. 측정값이 비어 있는 이유를 설명하고 목표치를 성과로 읽지 않는다.

## 시연 전 최종 확인

- 사용한 Run ID, 생성 시각, 모드, 시나리오, 최종 상태와 출력 파일을 메모한다. 발표 화면과 파일의 버전이 같은지 확인한다.
- 지도 연결 상태를 미리 확인한다. 지도 내부 조작이나 외부 연결이 지연되면 장소 목록에서 선택해 핵심 시연을 이어간다. 최신 지도 제공 방식·설정·제약은 [구현 명세](implementation-spec.md)를 따른다.
- 타미의 안내가 근거·수정 화면을 가리면 최소화한다. 타미가 유료 제작이나 승인을 대신 실행한다고 설명하지 않는다.
- 사진 귀속정보와 [이용 조건](place-sources.md#사진-귀속정보)을 확인한다. 실제 사진, AI 생성 이미지, 상상 문구를 구분한다.
- 다운로드 검수 JSON은 출력 시점 스냅샷이고 이후 담당자 승인 최신 기록은 앱 Run에 있다.
- 사진 구도 편집·AI 이미지 기능은 별도 질의응답에서 보여준다. 이번 3분 연습에서는 근거 확인과 수정 흐름의 시간을 확보한다.
- 실제 인터뷰, live 실행, 업무 비교를 새로 확보하면 위 대본의 해당 문장만 증거와 함께 갱신한다. 확보하지 못한 항목은 미확인으로 남긴다.
