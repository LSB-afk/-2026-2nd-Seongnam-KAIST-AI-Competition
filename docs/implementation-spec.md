# 성남 문화홍보 AI PD 구현 명세

공식 확인된 성남 관광지 8곳을 실제 지도에서 탐색하고, 선택한 장소의 사진과 근거로 한국어 카드뉴스 4장을 제작한다. 현재 범위는 [관광 플랫폼 설계](superpowers/specs/2026-09-13-tourism-platform-design.md)·[구현 계획](superpowers/plans/2026-09-13-tourism-platform.md), 실행 규칙은 [판단·검수 규칙](agent-rules.md), 검증은 [평가 문서](evaluation.md)를 따른다. [초기 기획](project-topic.md)의 판교박물관 단일 사례는 회귀·비교 이력으로 남긴다.

## 사용자 흐름과 완료 조건

대시보드 → 관광지 탐색·상세 → 선택한 장소의 홍보 목표 → 공식 근거 탐색 → 장별 작성·검수·부분 수정 → 사진 편집 → 재검수 → 담당자 승인 → 파일 전달 순서다. 장소·목표·대상은 `brief.placeId`·`brief.place`·`brief.goal`·`brief.audience`와 Place 문맥으로 전달한다.

산출물은 1080×1080 PNG 4장, 장별 문구·대본, 문장별 근거·출처 JSON, 검수·수정 이력 JSON, ZIP이다. 마지막 장에는 미래 문화공간을 상상한 장면임을 표시한다. 확인되지 않은 실제 사실을 상상으로 분류해 통과시키지 않는다.

서버가 현재 콘텐츠 버전의 검수, 미해결 항목 없음, 파일 구성·해시·버전 일치를 확인해야 `ready_for_approval`로 전환한다. 담당자 확인만 `approved`로 전환한다. 다운로드 직전에도 최신 버전과 상태를 다시 확인한다. 문구·사진 교체·크롭·AI 생성 결과를 저장하면 새 버전을 만들고 이전 검수·승인·파일 연결을 무효화한다.

## 탐색·카탈로그·기록

사이드바는 대시보드·관광지 탐색·카드뉴스 작업실·제작 기록으로 구성한다. 저장한 Run으로 통계와 최근 작업을 표시하고 이전 작업을 다시 연다. 데스크톱 탐색은 목록·지도·상세를 연결하고 좁은 화면에서는 목록/지도 전환과 상세 패널을 제공한다.

OpenStreetMap 래스터 타일과 Web Mercator 좌표를 사용한다. 전국 보기·성남 확대, 드래그·휠·버튼·키보드 이동, 인접 마커 묶음, 목록·마커 선택과 필터 동기화를 지원한다. 보이는 영역만 요청하고 지도에 출처를 표시한다. 타일 실패 시 재시도와 장소 목록을 유지한다. 경로 안내·실시간 혼잡도·전국 관광지 데이터는 제공하지 않는다.

`src/lib/places.ts`에는 판교박물관·율동공원·중앙공원·성남아트센터·모란민속5일장·성남시청·봉국사 대광명전·망경암을 등록한다. 이름·구·유형·설명·주소·좌표·확인일·공식 URL·짧은 공식 인용·사진 메타데이터를 보존한다. 미확인·상충 운영정보는 `null`과 필요한 설명으로 남긴다. 좌표는 공식 지도 마커이며 현장 출입구 측량값이 아니다. 세부 출처는 [장소·사진 출처](place-sources.md), 외부 UI와 지도/API 참조는 [디자인 참조](design-references.md)에 기록한다.

## 구조와 실행 경계

Next.js Node 서버, TypeScript, Node 24 내장 SQLite, HTML/CSS 카드와 Playwright 렌더러를 사용한다. 로컬 단일 프로세스의 전역 작업 관리자가 HTTP 요청 수명과 독립적으로 실행한다. SQLite의 Run JSON은 콘텐츠·출처·검색·검수·사용량·호출 이력을 보존한다. 종료되지 않은 실행은 재시작 시 검토 필요 상태로 복구한다.

| 실행 구분 | 수행 | 의미 |
| --- | --- | --- |
| fixture | 저장된 공식 발췌, 준비된 문구, 결정적 도구 선택과 검수 | API 없이 상태 전이·실제 파일 출력 확인 |
| live | 공식 본문 탐색과 실제 모델의 판단·작성·원자 검수 | API·모델·단가·비용 상한 설정 필요 |
| source_probe | 실제 공식 사이트의 제한된 탐색만 수행 | 모델 판단·콘텐츠 생성 없이 수집 연결 확인 |

`source_probe`는 CLI 검증 보고서 구분이며 앱 실행 모드는 fixture/live 두 가지다. 기록 재생 모드는 추가하지 않았다. live 실패를 다른 모드로 자동 대체하지 않는다. 키 없는 검증 환경에서는 live 텍스트 생성·수정과 실제 AI 이미지 품질을 검증하지 않는다. 모의 API 검증과 실제 공급자 호출을 구분한다. 이미지 생성 설정은 fixture/live 텍스트 모드와 별도로 검사한다.

## 총괄 에이전트와 도구

총괄 에이전트는 다음 행동, 예상 콘텐츠 버전, 대상 주장·카드, 근거 ID, 짧은 이유와 불확실성을 반환한다. 서버는 존재하는 ID와 허용 상태·상한을 검사한다. 내부 사고과정을 저장하지 않는다.

| 도구 | 입력·역할 | 주요 출력 |
| --- | --- | --- |
| `search_sources` | query, targetClaimIds, missingInformation, reason으로 필요한 정보 탐색 | 본문 스냅샷, 인용 위치, 검색 이력 |
| `compose_story` | 목표·대상·근거에 맞게 작성하거나 명시한 대상을 부분 수정 | 카드·주장과 수정 전후·이유·근거 |
| `verify_content` | 코드의 참조 검사와 별도 모델의 원자 의미 검수 | 판정·인용·권장 조치·과거 검수 스냅샷 |
| `render_cards` | 검수한 버전을 고정해 렌더링하고 한글·잘림 검사 | PNG·대본·JSON·ZIP과 해시 |

완료·보류는 각각 `finish`, `escalate`로 요청하지만 실제 전환 조건은 서버가 강제한다. 모델의 완료 선언만으로 파일을 승인하지 않는다.

## 목적 기반 공식 자료 탐색

선택한 관광지의 등록된 공식 URL을 탐색 시작점과 허용 범위로 사용한다. 판교박물관은 기존 FAQ·건립배경과 허용된 `/pangyo/` 콘텐츠를 유지한다. 다른 장소는 등록한 공식 안내·인용 출처 URL만 수집하며 리디렉션에도 같은 장소·경로·쿼리 검사를 적용한다. 검색 한 번의 상한은 8페이지·깊이 2·12초, 응답 2MB·신규 인용 32개다. 실행에 남은 시간이 더 짧으면 그 시간에 맞춰 중단한다. 임의 외부 사이트나 일반 검색엔진은 사용하지 않는다.

본문 영역·문단을 추출해 검색 목적에 맞는 문장을 후보 근거로 저장한다. 미리 등록된 문구와 정확히 일치해야만 수집하는 방식은 사용하지 않는다. 인용문은 저장 본문에 실제 존재해야 하며 문자 위치를 기록한다. 새 URL·본문 해시에는 새 스냅샷 ID를 부여하고 이전 버전의 근거를 덮어쓰지 않는다. 게시·수정일은 실제 메타데이터로 확인되는 경우만 기록한다.

검색 이력에는 방문 페이지, 신규 유효 인용 수, 관련 주장, 후속 검수에서 해결된 주장과 남은 정보를 담는다. 같은 인용을 여러 URL에서 찾았다고 신규 수를 부풀리지 않는다. 동일 질의에서 반복해 새 근거가 없으면 같은 검색을 계속하지 않고 다른 질의·수정·검토로 전환한다.

수집은 사실 지지 여부의 최종 판정이 아니다. 관람료 검색에서 무료 주차 안내가 나와도 관람료가 무료라는 근거로 채택해서는 안 된다. `npm run sources:probe -- 판교박물관 관람료`는 기존 박물관 수집 회귀용 명령이다. 실제 웹 연결을 확인하지만 선택한 8곳 전체의 모델 판단 정확도를 측정하지 않는다. 실행 결과는 웹 응답에 따라 달라진다.

## 원자 주장 검수와 이력

코드는 ID 연결, 원문 인용·위치, 본문·대본의 주장 연결, 상상 표시와 길이를 검사한다. live 모델 검수는 카드 4장의 제목·본문·대본 총 12필드를 분해한다. 분해 구간을 합치면 원문 전체가 정확히 복원돼야 하며, 사실 구간은 원자 평가에 연결해야 한다.

각 평가는 콘텐츠 내 위치, 원문, 주장 ID, 근거 ID, 근거와의 관계, 정보 시점, 짧은 이유, 후속 조치를 남긴다. 판정은 다음과 같다.

- `supported`: 근거가 해당 주장 전체를 지지한다.
- `contradicted`: 원문에 해당 주장과 충돌하는 정보가 있다.
- `insufficient`: 관련 정보가 없거나 부족해 판단할 수 없다.

부분 지지·인과관계 추가·최초 주장·현재 운영에 과거 자료 사용·출처 충돌을 구분한다. 비유·상상 속 실제 주장도 검수한다. 참조·구간·표시 조건은 서버가 검사하고 의미 판단은 모델이 맡는다. 모델 판정 자체도 오류 가능성이 있으므로 담당자가 원문을 확인한다.

새 버전의 검수 결과는 현재 판정으로 관리하고, 이전 버전의 판정·문제·연결 출처 스냅샷은 별도 검수 이력에 보존한다. 이미 해결된 과거 문제가 새 버전에서 자동으로 미해결로 되살아나지 않게 구분한다. fixture 의미 검사는 준비된 허용 문구의 데모이며 live 원자 의미 판단 성능을 대신하지 않는다.

## 부분 수정과 담당자 편집 보호

수정 대상 주장·카드와 예상 버전을 명시한다. 오래된 버전은 충돌로 처리하고, 문제가 없는 카드·주장 ID는 유지한다. 자동 수정 횟수는 콘텐츠 버전 수와 따로 계산한다.

담당자가 직접 편집한 카드는 보호한다. 자동 변경이 필요한 경우에는 원문을 덮어쓰지 않고 적용 전 제안과 이유·근거를 남겨 담당자 검토로 전환한다. ‘제안을 편집창에 불러오기’는 제목·본문을 복사할 뿐 저장이나 승인이 아니다. 담당자가 확인해 저장하면 새 버전이 되고 다시 검수해야 한다.

## 이미지 계약과 렌더링

`Card.image`는 자산 ID·placeId·종류(photo/upload/ai)·로컬 주소·SHA256·해상도·MIME·원출처·저작자·라이선스·생성 시각과 크롭(x/y 0~1, zoom 1~3)을 갖는다. 기본 사진은 권리를 확인한 `public/places/` 자산이다. 업로드·생성 자산은 기본 `data/images`에 저장한다. 사진 설명과 매니페스트는 [사진 귀속정보](place-sources.md#사진-귀속정보)를 따른다.

업로드는 사용·수정 권한 확인을 요구한다. PNG·JPEG·WebP의 실제 바이트와 최대 8MB·2천만 픽셀을 검사하고 재인코딩한다. 외부 이미지 URL이나 임의 파일 경로를 렌더러에 넘기지 않는다. 해시가 맞는 로컬 바이트를 data URI로 포함하고 렌더링 중 외부 네트워크를 차단한다.

사진 교체·크롭·AI 생성 완료는 한 카드만 변경한다. 문구와 다른 카드를 보존하며 새 버전·재검수·재승인을 요구한다. 문구 자동 수정은 기존 사진과 크롭을 보존한다. `imageJob`에 대상 카드·예상 버전·진행/성공/실패/취소·프롬프트를 기록하고 동시 작업과 오래된 응답을 차단한다. 실패·취소 시 원사진을 유지한다.

이미지 프롬프트는 장소·주제·구도·조명·색감·질감·참조 이미지·한글 문구 여백·상상 여부로 구성한다. 참조 사진이 있으면 이미지 바이트를 OpenAI 편집 API에 전달하고 없으면 생성 API를 사용한다. 한 번에 1024×1024 PNG 한 장을 요청한다. AI 생성 이미지 표시와 마지막 장의 상상 표시를 구분하고 한글은 HTML/CSS로 별도 합성한다. 참조 이미지의 원출처·저작자·라이선스를 함께 보존하며 CC BY-SA 파생 이미지에는 해당 이용 조건이 이어진다.

`OPENAI_API_KEY`·`OPENAI_IMAGE_MODEL`·`IMAGE_MAX_COST_USD_PER_CALL`·`MAX_COST_USD`가 필요하다. 이미지 요청도 기존 실행의 누적 시간·모델 횟수·비용을 사용한다. 호출 전에 예약액을 저장하며 성공 응답에도 실제 청구 USD가 없으므로 예약액을 보수적 추정값으로 유지한다. 실패를 무료로 확정하거나 자동 재시도하지 않는다. 키 없는 상태의 기본 사진 제작과 유료 이미지 생성을 구분한다.

## 상태·상한·호출 기록

`queued → running → ready_for_approval / needs_review / failed / cancelled`, `ready_for_approval → approved`를 사용한다. 편집 후에는 `needs_review`에서 재검수를 요청한다.

실행별 누적 상한은 도구 12회·모델 30회·자동 수정 3회·실행 시간 180초와 설정한 비용이다. 재검수해도 기존 호출·자동 수정·비용을 초기화하지 않는다. 담당자 검토 대기는 실행 시간에 포함하지 않는다.

네트워크 요청 전에 최대 비용을 예약·저장하고 실제 fetch 진입 시 API 시도 횟수를 기록한다. 토큰 사용량이 확인되면 거절·응답 잘림·JSON 실패에서도 먼저 정산한다. 확인할 수 없으면 예약액을 유지한다. 모델 ID, 프롬프트·검수 규칙 버전, 예약·성공·실패, 토큰·추정 비용·제한된 오류 설명을 저장한다. 비밀값이나 공급자 오류 본문을 호출 로그에 복사하지 않는다.

취소 후 늦게 온 응답이 취소 상태를 바꾸지 못하지만 확인된 사용량은 보존한다. 재시작 시 진행 중 실행의 예약액과 경과 시간을 보수적으로 유지한다. 카드 파일에는 출력 시점의 검수 스냅샷을 기록하며, 이후 finish 판단과 담당자 승인의 최신 기록은 Run에 남는다.

## API 계약

- `POST /api/runs`: `{brief, mode, strategy, scenario, requestId}`. 같은 요청 ID로 중복 생성을 방지한다.
- `GET /api/runs`, `GET /api/runs/:id`: 저장한 실행과 현재 상태·근거·검수·사용량 이력.
- `POST /api/runs/:id/{cancel,approve,edit,retry}`: edit는 `{version, cardId, title, body}`, approve는 `{version, reviewer}`, retry는 `{version}`.
- `GET /api/runs/:id/files/:name`: 현재 검수 버전과 파일 해시를 검사한 결과물.
- `POST /api/images`: `{data, mime, placeId, author, license}`. base64 raster 업로드 및 검증된 자산 저장.
- `GET /api/images/:id`: 검증한 로컬 업로드·생성 이미지.
- `POST /api/runs/:id/image`: `{version, cardId, operation}`. `crop`은 crop 값, `replace`는 assetId 또는 usePlacePhoto, `generate`는 선택 subject를 받는다.
- `POST /api/runs/:id/image-cancel`: `{version}`. 진행 중 이미지 생성 취소.
- `GET /api/config`: 텍스트·이미지 실행 설정 상태. 비밀값은 포함하지 않는다.

상태·버전 충돌은 409, 잘못된 입력은 400, live 설정 부재는 503이다. 보호된 카드의 수정 제안은 Run에 담기며 별도의 자동 승인 API를 두지 않는다.

## 평가·개발 목표·검증

기존 fixture 비교는 회귀로 유지한다. `eval:claims`는 별도 정답 파일을 모델에 노출하지 않는 합성 원자 주장 36개를 dev/holdout으로 평가한다. 모든 정답은 사람 미검토 초안이다. `eval:smoke`와 `eval:live`는 동일한 고정 자료·모델·도구·상한으로 baseline과 agent를 비교하고 자연 발생 과제와 주입 오류를 분리한다. 총 평가 비용은 `EVAL_MAX_COST_USD`와 디스크 예약 원장으로 관리한다. 실제 사람 승인·수정·시간은 측정 전 `null`이다.

앱의 모델 지시는 `src/lib/prompts.ts`에 판단·작성·검수를 분리해 버전별로 관리한다. [개발 재개 프롬프트](prompts/development.md)는 사용자에게 요청받은 경우 구체적 목표와 종료 조건을 Codex Goal로 추적하도록 한다. 활성 Goal이 있으면 이어서 수행하며, 구현·검증이 남아 있으면 완료로 표시하지 않는다. 별도의 앱 목표 관리 화면을 추가한 것은 아니다.

검증 순서는 핵심 회귀 → 전체 테스트 → 타입·린트·빌드 → production 브라우저 E2E → fixture 평가다. 외부 설정이 있으면 예산 안에서 live smoke를 별도로 실행하고, 없으면 해당 검증을 미완료로 명시한다. 현재 환경의 실제 모델 호출은 미검증이며 전체 검증 수치와 산출물은 최종 실행 결과로 갱신한다.

## 시각 설계와 범위

실제 장소 사진과 지도를 중심으로 밝은 배경·청색 브랜드·로컬 Noto Sans KR를 사용한다. 카드 출력은 사진 프레임, 장 제목, 편집 가능한 한국어 문구와 출처·종류 표시를 분리한다. 자체 도형은 인터페이스 보조 요소이며 실제 사진의 대체물로 표시하지 않는다. 1080×1080 PNG에서 한글 글꼴·이미지 로딩·크롭·텍스트 잘림을 확인한다. 브라우저는 1440/1024/390 너비와 키보드 접근·가로 넘침을 검증한다.

Node 24 이상 로컬 서버와 SQLite 저장이 현재 운영 범위다. 로그인·결제·공개 배포·SNS 자동 게시·등록되지 않은 관광지 자동 확장은 포함하지 않는다. 승인은 로컬 담당자 확인 기록이며 인증된 신원 증명이나 공개 게시 동작이 아니다.
