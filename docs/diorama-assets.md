# 성남 3D 여행 · 모형 자산 기록

갱신일: 2026-09-15. 현재 도시는 저장된 OpenStreetMap 좌표로 만든 Three.js 기하와 단색 재질을 사용한다. `city-model.ts`가 도시를 조합하고 `urban-model.ts`가 도로·건물·토지 피복을, `city-life.ts`가 사람·자동차를 만든다. 별도 다운로드 모델·생성형 이미지·외부 텍스처·실사 사진 투영은 사용하지 않는다. 지리 데이터의 귀속과 ODbL 조건은 [도시 지리 자료](seongnam-urban-sources.md), [구 경계·탄천 기록](seongnam-city-sources.md)에 있다.

## 현재 도시의 자산과 표현 범위

하나의 지속적인 모형에 세 구와 52개 명소의 위치 표지를 배치한다. 기존 8곳에 공식 자료로 확인한 44곳을 추가했고 관찰 지점은 총 55개다. 새 장소의 사진·운영시간·휴무·요금은 `null`로 유지한다. 좌표의 출처와 대표 지점의 의미는 [명소 확장 기록](seongnam-tourism-expansion-sources.md)을 따른다.

임의 격자 도로·배경 건물과 기존 명소의 상징 건축물은 현재 도시에서 제거했다. `models.ts`의 판교박물관·중앙공원·모란시장 세 독립 장면은 보존하지만 `buildCityModel()`이 불러오거나 원본 지도 위에 겹쳐 놓지 않는다. 아래 세 장면의 형상·자산 수치는 과거 독립 모델의 기록이다.

건물 높이는 OSM `height` → `building:levels`×3m → 기본 9m 순으로 결정하고 표시 높이는 1–300m로 제한한다. 등록 높이 자체도 측량값임을 보증하지 않는다. 도로 폭은 등록된 `width`를 우선하고 없으면 차로 수×3m 또는 도로 종류별 기본값을 적용한다. 교량 높이는 `bridge`·`layer`에 따른 추정이다. 이 추정은 원본 JSON 태그를 덮어쓰지 않는다.

지형은 평면이다. 탄천은 저장한 중심선에 폭 40m를 적용하며 실측 강폭·고도·제방을 복원하지 않는다. 별도 수면 자료에는 시 경계를 가로지르는 탄천 전체 면이 없다. OSM의 미등록 건물·점포·토지 피복과 제외 객체가 있으므로 모든 실제 시설이 수록됐다는 뜻이 아니다. 사람과 자동차는 등록된 이용 가능한 도로를 따라 움직이는 연출이며 실제 인구·실시간 교통·영업 현황이 아니다.

세계 좌표는 동쪽 +X, 북쪽 −Z, 위쪽 +Y이며 수평 10단위는 약 1km다. `buildCityModel()`은 생성한 도시 기하·인스턴스 자원을 소유하고 장소 선택 시 재생성하지 않는다. 반복 사람·차량은 인스턴싱하고 정적인 도로·건물·토지 피복은 공간별로 합쳐 렌더링한다.

## 보존한 세 독립 장면의 로컬 좌표·선택·애니메이션 계약

- 단위는 화면 구성용 임의 단위다. 실제 미터·위경도·방위·장소 간 거리를 뜻하지 않는다.
- 바닥 윗면은 `y = 0`, 주 정면은 `+Z`. 공통 장면 외곽은 약 `x = ±16`, `z = ±13`; 받침대 바닥은 `y = -1.8` 안팎, 모형 최고점은 `y < 10`이다.
- `buildDiorama(placeId)`는 `{ group, visitors, pickTargets, update, dispose }`를 반환한다. 허용 ID는 `pangyo-museum`, `central-park`, `moran-market`이다.
- `visitors`는 `group`에 포함된 독립 그룹이다. `visitors.visible`로 사람만 표시·숨김 처리한다.
- 렌더러가 정적 그림자 맵을 재사용하므로 움직이는 방문객은 그림자를 생성하지 않는다. 방문객을 이동·숨김 처리한 뒤 이전 위치의 그림자가 남는 문제를 방지하며 건물·나무의 그림자는 유지한다.
- `pickTargets`는 실제 선택 가능한 모형 객체다. 각 타깃과 모든 하위 메시의 `userData.hotspotId`에 같은 ID가 있어 재귀 레이캐스트 결과에서 바로 읽을 수 있다.
- `update(elapsedSeconds, moving)`에는 단조 증가하는 초 단위 시간을 전달한다. `moving = false`이면 사람과 장식 움직임을 정지한다. 재개 첫 프레임은 시간 기준만 다시 잡아 정지한 시간만큼 갑자기 이동하지 않는다. 시간 역행이나 비정상 값은 장면을 망가뜨리지 않게 무시한다.
- `dispose()`는 해당 빌드가 소유한 지오메트리·재질·텍스처·인스턴스 버퍼를 한 번씩 해제한다. 다른 장면과 GPU 자원을 공유하지 않는다. 호출 측이 카메라·조명·렌더러·컨트롤·애니메이션 루프를 관리한다.

모형 내부 간판은 외관의 위치와 명암을 위한 추상적인 기하 표현이다. 읽을 수 있는 장소명·관찰 지점명은 HTML UI가 제공한다. 모형 내부에 새 시설명·운영 정보·가격을 만들지 않는다.

| 장소 | 의미 있는 루트 그룹 | 관찰 지점 | 이름표 기준점 `[x, y, z]` |
| --- | --- | --- | --- |
| 판교박물관 | `pangyo-museum-building`, `museum-garden`, `museum-forecourt` | `museum-exterior` | `[2, 5, 3.4]` |
| 판교박물관 | 위와 같음 | `museum-garden` | `[-9, 1.2, 6.5]` |
| 중앙공원 | `central-park-lake`, `lakeside-korean-pavilion`, `faceted-park-forest`, `garden-footbridge` | `park-lake` | `[2, 0.3, 1]` |
| 중앙공원 | 위와 같음 | `park-pavilion` | `[-3.8, 3.5, -2.8]` |
| 모란민속5일장 | `moran-colorful-canopy-stalls`, `moran-market-walking-aisle`, `schematic-market-neighborhood` | `market-stalls` | `[-5, 2.8, 3.5]` |

이름표 기준점은 해당 장면의 좌표이며 타깃 메시의 로컬 좌표가 아니다. 각 타깃의 `userData.labelAnchor`에도 기록한다. 권장 전체 시점은 `[30, 26, 34]`에서 `[0, 2, 0]`을 바라보는 구도다. 1200×900, 수직 시야각 35°의 원근 카메라로 단독 시각 검수를 했다. 좁은 화면에서는 전체 받침대가 들어오도록 거리 또는 직교 카메라 범위를 조정한다. 근접 시점은 박물관 `[19, 14, 23] → [1, 3, 0]`, 정자 `[13, 12, 17] → [-3.8, 2, -3]`, 시장 `[18, 14, 22] → [0, 1, 0]`부터 조정할 수 있다.

## 현재 기하 구성과 검증

도시 지리 레이어는 약 75.6만 삼각형·72개 배치다. 도시 받침면·명소 표지·사람·자동차는 이 수치에 별도로 더해진다. 기본 밀도에서 전체 모형의 메시 220개 미만·삼각형 160만 개 미만을 `tests/diorama-city-model.test.ts`로 확인했다. 원본 형상·구멍·면 방향·높이와 도로 추정·자원 해제는 `tests/diorama-urban-model.test.ts`, 사람·차량의 경로·정지·재개·밀도는 `tests/diorama-city-life.test.ts`에서 검증한다.

이번 확장 작업의 단위·통합 테스트 696개, 전체 Chromium E2E 54개, 린트·TypeScript·프로덕션 빌드가 통과했다. 프로덕션 빌드의 Chromium 153·Apple M4 Pro Metal에서 데스크톱 기본 밀도와 모바일 에뮬레이션 최대 밀도(7,200명·3,000대)를 각각 120프레임 측정해 평균 16.67ms·P95 16.7ms, 약 60fps를 확인했다. 모바일은 같은 컴퓨터의 390×844·DPR2 에뮬레이션이다. 개발 빌드의 소프트웨어 GPU(ANGLE SwiftShader) 60프레임 표본은 평균 419.7ms·P95 433.4ms로 느렸다. 물리 휴대폰·Safari·저성능 GPU 검증은 남아 있다. 최신 결과는 로컬 `outputs/seongnam-living-city-development/`에 보관한다.

## 이전 세 독립 장면의 시각 검수와 검증

형상·레이캐스트·자원 소유권·방문객의 정지 및 재개는 `tests/diorama-models.test.ts`에서 실제 Three.js 객체로 검증한다. 브라우저의 조명, 그림자, 카메라 구도, 화면 크기별 가림 현상은 별도로 렌더링해 검수한다. 메시 수나 삼각형 수만으로 실제 프레임 속도를 보장하지 않는다.

모델 단독 검증: `npm test -- tests/diorama-models.test.ts` → 15개 통과. `npx eslint src/lib/diorama/models.ts tests/diorama-models.test.ts` → 통과. 브라우저에서 세 기본 구도를 렌더링해 확인했고, 첫 검수에서 발견한 시장 천막의 면 방향을 수정한 뒤 다시 검수했다. 기본 구도에서 박물관의 목재·벽돌·유리 면, 공원의 기와 정자·호수·산책길, 시장의 천막·곡물 좌판을 구분할 수 있었다. 이 단독 검증은 통합 UI·모바일 조작·실기기 FPS 검증을 대신하지 않는다.
