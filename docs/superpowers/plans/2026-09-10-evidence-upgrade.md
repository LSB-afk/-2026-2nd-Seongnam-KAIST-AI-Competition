# 근거 탐색·검수 고도화 구현 계획

사용자가 2026-09-10 승인한 다음 개발용 프롬프트를 실행한다. Codex Goal에 완료 목표를 등록한다. 앱의 기존 brief.goal은 모델 문맥으로 유지하며 추가 목표 관리 UI는 별도 사용자 요청이 있을 때만 확장한다.

## 설계와 책임

기존 Run JSON 저장 구조에 선택 필드로 검색 이력, 불변 출처 스냅샷, 원자 주장 평가, 검수 이력, 호출 기록, 자동 수정 횟수, 담당자 보호 영역을 추가한다. 기존 레코드는 필드 누락 시 빈 이력으로 읽는다. root가 types.ts, agent.ts, service.ts, run.ts 및 통합을 소유한다.

1. 자료 수집: sources.ts와 sources.test.ts. SearchIntent → 공식 판교 영역 제한 탐색 → SourceResult(search 포함). 새 URL/본문 해시마다 새 ID; 근거 인용은 snapshot.slice(start,end)와 일치. 고정 HTML로 신규 사실, 문구 변경, 무관 본문, 중복·리디렉션·취소를 먼저 검증한다.
2. 모델·검수: provider.ts, verifier.ts, prompts.ts 및 해당 테스트. 작성/판단/원자 검수 프롬프트 분리·버전 부여. 각 title/body/script 전체를 검수하고 사실 부분은 ClaimAssessment로 반환. 서버는 위치·ID·인용 무결성을 검사한다. API 예약·정산을 로그와 함께 저장한다.
3. 실행·편집: agent.ts, service.ts 및 테스트. 검색 결과 누적, 진전 없는 동일 검색 차단, 자동 수정 3회와 버전 별도 계산, 해당 카드만 수정, 사람 편집은 제안으로 보류, 과거 검수 스냅샷 유지. 먼저 덮어쓰기·편집 보호 회귀를 실패시킨다.
4. 제작실: page.tsx, globals.css. 실행 모드/API 호출, 검색 결과, 원자 주장 원문 연결, 수정 제안 및 과거 검수, 한도 대비 사용량을 기존 화면에 통합한다. SSR/클라이언트 가이드를 읽고 E2E로 검증한다.
5. 평가: scripts 및 tests 평가 파일. 30개 균형 주장 자료/초안 정답을 분리, dev/holdout 분리, fixture와 live 결과 분리, 동일 자료·예산 비교, 총 평가 비용 예약을 디스크에 저장한다. 사람이 검증하지 않은 지표는 초안 기반으로 명시하고 사람 평가는 null로 유지한다.
6. 통합 검증: 기존68개 기준선 통과 확인 완료. 변경별 테스트 → 전체 test/typecheck/lint/build → 실제 production E2E → fixture 평가. 실제 API 설정이 있으면 설정 예산 내 smoke/live 수행, 없으면 설정 누락만 명시하고 나머지 완료. 외부 사이트 탐색은 별도 통합 확인한다.

## 불변 조건

판교박물관 한국어 4장, 마지막 상상 표시, 승인·파일 버전 일치, 비용·시간·호출 상한과 취소/복구 유지. 신규 의존성·SNS·공개 배포·이미지 권한 추정 없음. 기록 재생 기능은 이번 범위에 추가하지 않는다. 불필요한 전체 재작성 대신 작은 부분 변경을 택한다.

## 완료 증거

목적 있는 검색의 새 근거, 근거 부족/충돌 구분, 원자 주장·인용·수정 연결, 사람 편집 보호, 과거 스냅샷 보존, 현재 버전 승인/ZIP, 회귀 및 브라우저 통과를 확인한다. 실제 API 미설정은 성공으로 위장하지 않는다. README·규칙·평가·3분 시연 문서를 최종 동작에 맞춰 갱신한다.
