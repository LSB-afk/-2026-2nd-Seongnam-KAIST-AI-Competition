# Apple iPhone Duo 공식 디자인 레퍼런스 확인

검증일: 2026-09-13. 조사 유형: 공식 웹페이지의 실제 구현·반응형 디자인 참고 조사. 요청한 URL은 **정상 확인**했다. 대체 페이지를 사용하지 않았다.

## 공식 자료와 검증 범위

- 공식 원문: [Apple 대한민국 iPhone Duo](https://www.apple.com/kr/iphone-duo/).
- 공식 웹 조회와 Playwright Chromium 실제 탐색 모두 확인했다. 데스크톱 **1,440 × 1,000**, 모바일 폭 **390 × 844**, 기기 배율 1이다. 두 경우 모두 HTTP **200**, 최종 URL은 요청 URL과 동일했다.
- 디자인 수치는 공식 디자인 가이드의 규정이 아니라, 해당 날짜의 실제 페이지 DOM·computed style·화면을 측정한 값이다. 반응형 크기·애니메이션 시점·폰트에 따라 달라질 수 있다.
- 스크린샷을 직접 열어 대표 이미지, 제목, 섹션 구성, 크롭, 갤러리, 펼침 상태를 확인했다. 공식 Apple 이미지 파일을 우리 제품 자산으로 복사하지 않았다.

Hero는 작은 제품명 → 큰 메시지 → 짧은 보조 안내 → 큰 제품 사진 → CTA 순서다. 다음에는 핵심 특징 갤러리, 디자인 이야기, 자세히 살펴보기, 개별 기능 이야기가 이어진다. 모든 정보를 첫 화면에 동시에 노출하지 않는다. 측정한 기본 폰트 스택은 SF Pro KR, SF Pro Text, Apple Gothic 등을 포함한다. 이것을 우리 서비스의 폰트 사용 권한으로 해석하지 않는다.

공식 대표 이미지의 실제 로딩 URL:

- [데스크톱 hero end frame](https://www.apple.com/kr/iphone-duo/images/overview/media-hero/hero_endframe__gdt3l3spaqie_large.jpg): 브라우저 natural size 966 × 640px. 화면에서는 1,044 × 692px로 표시되어, Apple 자체 페이지에서도 표시 크기가 원본 픽셀과 항상 일치하지는 않는다.
- [모바일 hero](https://www.apple.com/kr/iphone-duo/images/overview/media-hero/hero__dbnzxlb3ia2q_small.jpg): natural size 740 × 570px. 데스크톱과 별도 자산을 사용한다.

## 실제 동작과 정보 펼침

- 주요 특징 갤러리: 이미지와 짧은 설명을 큰 카드 한 장으로 제시한다. 하단에 진행 점과 일시정지 제어가 있고 다음 카드의 가장자리가 보인다. 초기 viewport 밖 이미지는 작은 placeholder였으며 스크롤 후 실제 사진이 로딩됐다. 이는 lazy loading 관찰이며 로딩 오류로 판정하지 않았다.
- 자세히 살펴보기: 데스크톱에는 왼쪽의 짧은 항목 목록과 오른쪽의 큰 제품 이미지가 있다. 항목 옆의 더하기 아이콘이 상세 설명을 여는 단서다. 모바일에서는 제품 이미지 아래에 짧은 선택 항목·설명 패널과 좌우 이동 버튼을 둔다.
- 모바일의 상세 항목 클릭은 실제 성공했다. `aria-expanded=false`에서 `true`로 바뀌고, 해당 기능 설명이 회색의 둥근 패널에 나타났다. 스크린샷은 `apple-reference-mobile-detail-open.png`에 저장했다.
- 색상 선택과 접힘 각도 range 입력은 공식 문서·DOM에서 존재를 확인했다. 실제 색상 전환·드래그 동작까지 검증하지 않았으므로 상호작용 성공으로 계산하지 않는다.
- 두 viewport의 초기 페이지 JS 오류와 실패 요청은 각각 0건이었다. 추가 스크롤·상세 탐색 중 수집한 console error도 0건이었다. 이는 해당 관찰 구간의 결과이며 전체 사이트 무오류 보증이 아니다.

## 성남 서비스 적용 권고 — 관찰과 구분한 제안

1. 첫 화면에는 서비스명, 짧은 가치 설명, 대표 장소의 큰 실제 사진, 제작을 시작하는 CTA를 둔다. 사진 위에 여러 상태 상자와 설명을 덮어 읽기 부담을 만들지 않는다.
2. 소개 화면의 흐름은 장소의 매력 → 선택 가능한 실제 장소 → 카드뉴스 만드는 방법 → 제작 진입으로 잡는다. Apple의 긴 제품 서사 전체를 작업 도구에 그대로 옮기지 않는다.
3. 데스크톱은 80~90px 안팎, 모바일은 24px 안팎의 좌우 여백을 출발점으로 삼되, 제작 폼과 결과 미리보기의 공간에 맞춰 조절한다. 섹션 상하 128/80px, 제목 48/32px는 소개 구간의 출발값으로 사용할 수 있다.
4. 실제 작업 중에는 장소·대상·목표·필수 옵션과 현재 진행 상태를 항상 알아볼 수 있게 유지한다. 출처 상세·검증 설명·고급 설정은 제목이 명확한 펼침 패널로 둔다. 제출에 필요한 오류나 승인 상태는 펼침 안에 숨기지 않는다.
5. 장소 선택은 큰 사진과 한 줄 설명을 사용한다. 모바일 가로 갤러리는 다음 항목이 조금 보이게 하거나, 목록 탐색이 더 쉬우면 세로 목록을 쓴다. 가로 스와이프만 유일한 접근 경로로 만들지 않는다.
6. 사진은 장소별 구도를 확인해 크롭한다. 율동공원 같은 파노라마와 건물 전경을 동일하게 다루면 피사체가 잘릴 수 있으므로, 실제 장소 정체성이 보이는 위치를 우선한다. 사진 저작자·출처는 결과물과 가까운 곳에서 확인할 수 있어야 한다.
7. 본문 색과 밝은 배경 교차를 기본으로 쓰고, 파란색은 주 행동과 선택 상태에 제한한다. Apple의 버튼 치수 자체를 접근성 규정으로 간주하지 않는다. 특히 모바일 주요 동작은 더 넉넉한 터치 영역을 둘 수 있다.
8. 애니메이션은 정보를 가리지 않는 범위로 줄이고, 결과 확인·수정·승인 단계에서는 예측 가능한 정적 상태를 우선한다. 이미지·문구·폰트는 우리 서비스 자산을 사용한다.

## 미확인 사항과 한계

- 데스크톱 상세 펼침은 레이아웃·더하기 아이콘의 존재까지 확인했고 자동 클릭 성공은 미확인이다. 모바일 상세 펼침 성공과 구분한다.
- 실제 iOS Safari, Android Chrome, 키보드 전체 이동, VoiceOver, reduced-motion 환경은 검증하지 않았다. 모바일은 Chromium의 390px viewport 검증이다.
- 모든 하위 섹션의 전체 문구·애니메이션·AR·영상 재생·구매 흐름은 조사 범위 밖이다.
- 전역 모바일 메뉴 자동 클릭은 최초 선택자 불일치로 검증하지 못했다. 메뉴 아이콘의 시각적 존재와 반응형 탐색 배치는 확인했다.
- 기준 페이지는 정상 확인했으며 대체 공식 페이지나 제삼자 디자인 사례는 사용하지 않았다. 상품 성능·출시 일정은 이 디자인 조사에서 독립 검증한 주장으로 재사용하지 않는다.
