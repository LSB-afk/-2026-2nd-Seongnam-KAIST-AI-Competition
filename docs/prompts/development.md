# 다음 개발을 이어갈 때 사용하는 프롬프트

아래 프롬프트는 개발 에이전트용이다. 앱의 실제 모델 지시는 `src/lib/prompts.ts`에서 버전별로 관리한다.

```text
성남 타임스토리의 현재 브랜치와 문서·테스트를 읽고, 사용자가 요청한 개선을 구현부터 검증까지 완료하라.

Codex Goal 기능을 사용할 수 있으면 이번 작업의 구체적인 목표와 종료 조건을 등록하라. 이미 활성 Goal이 있으면 중복 생성하지 말고 이어서 수행한다. Goal이 구현 완료를 대신하지 않는다. 핵심 작업과 검증이 남아 있으면 완료로 표시하지 않는다.

판교박물관 한 곳, 한국어 카드뉴스 4장, 마지막 상상 장면, 담당자 승인, 로컬 실행 범위를 유지한다. 신규 의존성·공개 배포·자동 게시·이미지 권한 추정을 추가하지 않는다.

README.md, docs/agent-rules.md, docs/evaluation.md와 관련 코드를 먼저 읽는다. 기존 테스트를 확인하고 이번 변경으로 실패해야 하는 회귀 사례를 먼저 추가한다. 실행 가능한 명세와 데이터 계약을 확정하고 독립적인 작업만 native subagent에 위임한다. 공통 타입·상태 전이는 한 책임자가 통합한다.

자료 수집은 목적과 누락 정보를 받아 공식 읽기 전용 페이지에서 찾는다. 인용·본문 위치·출처 해시·검색 이력을 기록한다. 기존 스냅샷은 덮어쓰지 않는다. 새 근거가 없는 검색은 반복하지 않는다.

제목·본문·대본의 사실을 각각 검수한다. 사실 전체가 지지되면 supported, 반박 근거가 있으면 contradicted, 정보가 부족하면 insufficient다. 공식 URL, 문장에 포함된 일부 진실, 상상 라벨만으로 주장을 통과시키지 않는다. 검수 모델 출력도 서버에서 참조·위치·누락을 확인한다.

수정은 해당 카드와 주장에 제한한다. 예상 버전을 확인하고, 사람의 편집은 덮어쓰지 않고 제안으로 남긴다. 새 문구는 검수·승인을 무효화한다. 자동 수정 횟수와 전체 버전 수를 구분한다.

모델 호출 전 비용을 예약·저장하고, 파싱 실패·취소 후에도 확인된 사용량을 기록한다. 평가에는 실행별 한도와 전체 평가 한도를 모두 적용한다. fixture·live를 분리하고, API 설정이 없으면 가능한 구현과 모의 검증을 끝낸 뒤 live만 미검증으로 명시한다. 실제 호출 실패를 준비된 응답으로 바꾸지 않는다.

비교 평가는 같은 자료·모델·도구 권한·상한으로 수행한다. 평가 정답은 대상 모델에 전달하지 않는다. 사람이 검증하지 않은 정답은 초안, 사람 승인·검토 시간은 측정 전 null이다. 유리한 결과만 골라 보고하지 않는다.

변경별 테스트 → 전체 테스트 → 타입·린트·빌드 → production E2E → 평가 순서로 확인한다. 실제 결과에 맞춰 판단 규칙·평가·시연 문서를 갱신한다. 종료할 때 구현·검증 완료 항목, 외부 설정으로 남은 검증, 실제 수치, 변경 파일, 재현 명령을 분리해 보고한다.
```
