# 검증 및 비교 평가

## 재현 명령

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run test:e2e
npm run eval
```

`npm run eval`은 동일한 공식 원문 발췌와 실제 PNG/ZIP 렌더러로 baseline과 agent를 비교한다. 결과는 `outputs/evaluation/results.json`, `results.csv`에 저장한다. fixture의 모델 응답과 판단은 결정적 테스트 더블이다. 실제 LLM 품질·사람의 시간 절감·승인율을 입증하지 않는다.

## 준비된 사례와 기대 결과

| 사례 | 기대 결과 |
| --- | --- |
| normal | 검수 통과와 실제 카드 파일 제공 |
| causal | 근거 없는 역사적 계승 표현 제거, 재검사 |
| future | 확정 사업 표현 제거, 상상 표시 |
| mismatch | 문장과 맞지 않는 출처 사용 발견 및 수정 |
| unavailable | 확인된 근거가 없어 담당자 검토로 전달, 파일 없음 |
| persistent | 반복 상한 내 중단, 미해결 항목 표시 |

2026-09-10 최초 fixture 비교에서 두 방식 모두 6개 중 4개를 승인 대기 상태로 만들고 2개를 보류했다. 정상 사례는 agent 4회 / baseline 6회 도구 호출이었다. 오류 수정 사례는 agent가 추가 검색을 수행해 7회 / baseline 6회였다. 지속 오류는 agent가 더 많은 호출을 사용했다. 이 결과로 에이전트가 더 정확하거나 저렴하다고 결론 내리지 않는다.

## 회귀 및 별도 경계 사례

시연 문구와 별개로, 정상 개관일에 허위 정보를 덧붙인 문장, 삭제된 문장 ID를 참조하는 과거 문제, 수동 편집 보존, API 사용량 미보고·거절·잘린 응답·과금 상한, 취소 후 늦은 응답, 실행 중 재시작, 읽는 중 버전 변경, 외부 호스트·로컬 주소, HTML 주입, 한글 overflow를 단위·통합 테스트로 검사한다.

Playwright E2E는 브라우저에서 실제 UI/서버/SQLite/렌더러를 연결한다. 오류 복구 후 근거 확인, 승인, ZIP 다운로드 및 1080×1080 PNG 4장, 복구된 카드의 수동 수정 후 승인 무효화·재검수, 자료 부재, 잘못된 API 요청, 모바일 가로 넘침을 검사한다.

## 실제 모델 평가를 위한 후속 절차

1. 사용할 모델과 공식 가격을 설정하고 live 전체 경로가 동작하는지 먼저 확인한다.
2. 시연에 사용하지 않은 요청·주장·근거 쌍을 사전에 작성하고 정답은 별도로 보관한다.
3. 같은 자료 스냅샷, 모델, 도구 권한, 예산으로 두 방식을 여러 번 실행한다.
4. 사람이 원문과 최종 문장을 확인해 누락 오류, 오탐, 승인 가능 여부를 기록한다.
5. 개입·수정 횟수, 요청부터 승인까지 시간, 토큰·도구·비용, 실패·중단을 함께 비교한다.

현재 CSV의 `humanApproved`, `humanEdits`는 실제 담당자 측정 전이므로 비어 있다. AI가 이를 추정해 채우지 않는다. live 비교용 과제와 실제 사람 평가 결과는 아직 없다.
