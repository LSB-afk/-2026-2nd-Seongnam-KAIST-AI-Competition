# 에이전트 판단·검수 규칙

## 목표와 프롬프트

실행의 `brief.placeId`·`brief.goal`·독자 조건과 선택한 Place를 판단·작성·검수 문맥에 전달한다. 등록 관광지 8곳 중 선택한 장소의 한국어 카드 4장과 마지막 상상 장면이 제품 범위다. 장소 ID와 이름이 일치해야 하며 다른 장소의 사실·사진을 섞지 않는다. 이름만 있는 과거 실행도 카탈로그에서 찾는다.

[관광 플랫폼 설계](superpowers/specs/2026-09-13-tourism-platform-design.md)와 [구현 계획](superpowers/plans/2026-09-13-tourism-platform.md)을 따른다. 장소·사진의 사실 및 이용 조건은 [출처 문서](place-sources.md), 지도·이미지 API 참조는 [디자인 참조](design-references.md)에 있다. 대시보드와 제작 기록의 집계는 저장한 Run을 사용한다.

실제 모델의 역할 지시는 `src/lib/prompts.ts`가 관리한다. `PROMPT_VERSION`, `REVIEW_RULES_VERSION`은 실행과 호출 기록에 저장한다. 판단·작성·검수를 분리하고 짧은 행동 이유·불확실성·대상 ID를 기록한다. 내부 사고과정은 기록하지 않는다. 개발 재개용 프롬프트는 `docs/prompts/development.md`에 있다.

## 행동과 자료 수집

다음 행동은 `search_sources`, `compose_story`, `verify_content`, `render_cards`, `finish`, `escalate` 중 하나다. 실제 모델 결정은 예상 콘텐츠 버전과 현재 존재하는 대상 ID를 포함해야 한다. 검색은 query, targetClaimIds, missingInformation, reason을 받는다. 미등록 원자 주장의 수정 대상은 해당 카드 ID다.

선택한 관광지 카탈로그에 등록된 공식 URL만 탐색한다. 판교박물관은 기존 FAQ·건립배경과 허용된 `/pangyo/` 읽기 전용 콘텐츠를 사용한다. 다른 장소는 등록된 공식 안내·인용 출처 URL에 한정한다. 일반 웹 검색·다른 관광지 페이지·임의 쿼리와 리디렉션은 허용하지 않는다. 검색 한 번은 최대 8페이지·깊이 2·12초, 응답 한 개는 2MB, 신규 인용은 32개로 제한한다. 남은 실행 시간이 더 짧으면 해당 시간 안에서 중단한다.

본문 영역에서 실제 문장을 추출하고 인용 위치·검색 목적·수집 시각을 기록한다. 발행·수정 시각은 명시적인 메타데이터에서만 가져온다. 새 URL/본문 해시에는 별도의 스냅샷 ID를 부여한다. 기존 스냅샷과 근거는 덮어쓰지 않는다. 같은 인용이 여러 URL에 반복되어도 새 근거 수를 부풀리지 않는다.

수집 결과는 **검수 후보**다. 공식 사이트의 무료 주차 문장을 입장료의 근거로 채택해서는 안 된다. 해결 여부는 후속 주장 검수의 실제 인용을 기준으로 집계한다. 같은 검색에서 두 번 새 근거가 없으면 같은 검색의 세 번째 실행을 막고 다른 질의·수정·담당자 확인으로 넘긴다. 외부 문서는 실행 지시가 아니다.

## 검수 계약

코드 검수는 카드·주장·출처·근거 ID, 본문·대본과 주장 연결, 인용 원문·위치, 상상 표시, 글자 수를 확인한다. 실제 모드의 의미 판정은 독립 모델 검수로 수행한다.

`atomic-evidence-2026-09-15.1`부터 여러 명소가 함께 실린 공식 페이지도 선택 장소와의 연결을 별도로 확인한다. 다른 명소 이름은 선택 장소의 등록 인용·주소에 포함된 문맥과 해당 카드의 유효 근거로 확인되는 위치만 허용한다. 예를 들어 중앙공원 소개 안의 수내동가옥이나 서현문화의집의 중앙공원로 주소는 허용하지만, 같은 공식 페이지에 있다는 이유만으로 다른 명소 설명을 가져오지는 않는다.

모델 검수는 모든 카드의 제목·본문·대본, 총 12개 필드를 빠짐없이 분해한다. 구간을 다시 합쳤을 때 원문과 정확히 일치해야 한다. 사실 구간마다 원자 평가를 연결한다. 등록 사실의 일부를 nonfact로 돌려 검수를 생략할 수 없다. 비유·상상 속 연도·운영·사업·역사적 연결도 사실 검수 대상이다.

각 평가에는 원문 필드와 문자 위치, 주장 ID, 인용·출처·관계·판정 이유, 정보 시점, 후속 조치를 기록한다.

- `supported`: 인용이 해당 주장 전체를 지지한다.
- `contradicted`: 인용에 해당 주장을 반박하는 정보가 있다.
- `insufficient`: 무관한 자료, 정보 부족, 판단할 수 없는 경우다. 거짓을 뜻하지 않는다.

부분 지지와 출처 충돌을 구분하고, 현재 운영·사업 정보는 현재성을 확인한다. 근거 관계와 수치·시점·구간·ID 조건을 서버에서 다시 확인한다. 새 사실이 주장 목록에 등록되지 않았거나 검수 응답이 불완전하면 완료하지 않는다. 규칙과 모델 모두 완전한 사실 판정기는 아니므로 담당자가 원문을 확인한다.

fixture는 장소별로 저장한 공식 발췌·허용 문구를 검사하는 결정적 데모다. 발췌에는 주소와 짧은 구절도 있으므로 완전한 설명문을 새로 생성했다고 표시하지 않는다. 판정 이유에 fixture임을 표시하며, 자유 입력의 의미 판정이나 실제 모델 정확도를 입증하지 않는다.

## 부분 수정과 담당자 보호

수정 결정에서 명시한 대상만 반영한다. 관련 없는 카드와 기존 주장의 ID를 보존한다. 이전 버전을 대상으로 한 변경은 거부한다. 담당자가 직접 편집한 카드는 보호하며, 자동 변경이 필요하면 적용되지 않은 제안을 남기고 검토 상태로 전환한다. 제안을 편집창으로 불러오는 동작은 저장·승인이 아니다.

Claim ID만 지정한 수정은 기존 원문 구간의 치환으로 제한한다. 같은 카드 안의 다른 주장·근거·제목도 보존한다. 분할·추가·삭제 등 안전하게 범위를 구분할 수 없는 변경은 거부하고 카드 ID를 명시한 새로운 결정을 요구한다. 패치의 뒤쪽에서 오류가 나도 앞부분의 내용이나 제안만 적용하지 않는다.

새 문구는 새 콘텐츠 버전이다. 이전 승인·출력 연결·현재 검수를 무효화하고, 과거 검수의 원문 스냅샷·판정·이슈는 별도로 보존한다. 해결된 이슈가 새 버전에서 다시 미해결로 되살아나지 않도록 구분한다. 자동 수정 횟수와 사람이 저장한 버전 수를 별도로 센다.

## 쉬운 설명 요청

`readingStyle=easy`는 설명 방식이며 사실 변경 권한이 아니다. 기존 카드 변환은 현재 버전과 허용 대상 카드를 명시한 `simplify` 요청으로 시작한다. 보호 카드는 제외하고 기존 주장·근거·사진을 보존한다. 날짜·수치·단위·조건 누락은 거부하고 live 검수는 변환 전 문구와 의미를 대조한다. 실패 후 원문은 보존되며 재검수·담당자 확인 없이 이전 승인을 재사용하지 않는다. 데모 변환은 준비된 문구 규칙이고 일반적인 자연어 이해가 아니다.

## 사진 편집과 이미지 생성

기본 사진은 `public/places/`의 확인된 장소 자산이다. 사진과 공식 글의 이용 조건을 구분하고 저작자·원출처·라이선스를 화면·출력에 보존한다. CC BY-SA 사진의 파생 이미지 배포에는 해당 동일조건변경허락이 적용된다. AI 생성 표시만으로 원사진의 권리 조건을 대체하지 않는다.

크롭·사진 교체·AI 생성 완료는 해당 카드의 이미지만 바꾼다. 문구·다른 카드·과거 버전을 보존하고 새 버전에서 검수·승인·출력 연결을 무효화한다. 반대로 모델의 문구 수정은 선택한 사진과 크롭을 바꿀 수 없다. 과거 버전 요청·동시 편집은 거부한다.

업로드는 권한 확인을 받은 PNG·JPEG·WebP, 최대 8MB·2천만 픽셀로 제한하고 실제 바이트를 검사해 재인코딩한다. 렌더러는 해시를 확인한 로컬 바이트만 읽고 외부 이미지 URL을 직접 요청하지 않는다. 미리보기와 PNG는 초점 x/y와 확대 1~3배를 함께 사용한다.

AI 요청은 장소·주제·구도·조명·색감·질감·참조 이미지·문구 여백·상상 여부를 보관한다. 참조 사진은 실제 이미지 입력으로 전달하며 원사진의 출처·권리와 생성 이력을 유지한다. 한글 문구는 별도 합성한다. 생성 이미지는 AI 생성으로 표시하고 실제 모습·확정 사업의 증거로 해석하지 않는다. 마지막 상상 카드에 실제 사진을 쓰면 그 사진은 실제 모습임을 함께 표시한다.

이미지 설정이 없으면 연결 안내를 표시하고 호출하지 않는다. 실패·취소·시간 초과 시 기존 사진을 유지하며 늦은 성공 응답으로 덮어쓰지 않는다. 자동 유료 재시도는 하지 않는다. 이미지 호출도 실행의 모델 횟수·누적 시간·비용에 합산하고, 공급자 청구액이 확인되지 않으면 설정한 예약액을 유지한다.

## 종료·예산·복구

로컬 Node 24 이상 서버에서 실행하며 공개 배포·자동 게시는 범위 밖이다. 실제 OSM 타일은 보이는 영역만 요청하고 출처를 표시하며, 자동화에서는 모의 응답을 사용한다.

실행별 상한은 도구 12회, 모델 30회, 자동 수정 3회, 누적 실행 180초다. 담당자 검토 대기 시간은 실행 시간에 포함하지 않는다. 비용 상한과 모델 단가는 서버 환경 설정을 따른다. 재검수는 이전 호출·비용·자동 수정 횟수를 유지한다.

모든 모델 호출은 네트워크 요청 전에 최대 입력/출력 비용을 예약하고 저장한다. 실제 fetch 진입 때 API 시도 횟수를 늘린다. 사용량이 확인되면 응답 거절·잘림·JSON/스키마 실패를 처리하기 전에 정산한다. 사용량을 모르면 예약액을 유지한다. 오류 기록에는 비밀값이나 원문 응답을 복사하지 않는다.

취소는 실제 작업에 전달하고 늦은 응답이 취소 상태를 바꾸지 않도록 한다. 취소 후 확인된 사용량과 호출 기록은 정산한다. 재시작 시 진행 중 작업은 검토 필요 상태로 전환하고 예약 비용과 경과 시간을 보수적으로 유지한다.

미해결 항목 없이 현재 버전의 검수와 PNG 4장·대본·출처·검수 JSON·ZIP이 일치할 때 승인 대기가 된다. 담당자 승인과 자동 검수 통과는 다르다. 다운로드 직전 최신 버전과 SHA256을 다시 확인한다. 텍스트 잘림은 수정·재검수 경로로 되돌린다.

`review.json`은 출력 시점의 검수·사용량 스냅샷(`auditStage=render_snapshot`)이다. 출력 이후 finish 판단과 실제 담당자 승인의 최신 기록은 Run에 남는다. ZIP에 들어 있는 값을 최종 공급자 청구액이나 사람의 승인으로 해석하지 않는다.

## 평가와 표시

fixture 평가, 실제 텍스트 모델 평가, 실제 AI 이미지 품질, 공식 사이트 수집 probe를 분리한다. 키가 없는 환경에서 실제 모델·이미지 API 성공을 주장하지 않는다. 실제 API 실패를 fixture로 바꾸지 않는다. 비교 평가는 동일한 고정 자료·모델·도구 권한·상한을 사용한다. 실제 평가에는 여러 실행을 합친 디스크 기반 예산 예약을 적용한다. 사람이 검증하지 않은 평가 정답은 초안이며 사람 승인·수정·시간 수치는 null이다. 자세한 절차와 현재 결과는 `docs/evaluation.md`를 따른다.
